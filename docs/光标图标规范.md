# 光标图标规范

> 前台（`apps/web`）全站鼠标光标的唯一规范。图形母版在
> `packages/design-tokens/cursors/src/`，CSS 挂载在
> `apps/web/src/styles/app.css` 的 `:root`。
>
> 与本文件冲突的旧描述一律以本文件为准；`设计语言-Token规范.md` §4.6 只是索引。

---

## 1. 设计理念

借尼康取景器**对焦点（AF point）**的语言来做交互反馈。取景器里对焦点的形态变化
本身就携带语义，直接映射过来即可，不需要再造一套图形隐喻：

| 相机里的含义 | 交互里的含义 |
| --- | --- |
| 单点 AF 框待命 | 正常状态：这里没有可点的东西 |
| 对焦框亮起（合焦） | 悬停可点：这里可以点 |
| 焦点收窄成微点 | 按下：已经点下去了 |
| 动态区域 AF（主点 + 环绕副点） | 拖拽：这块可以拖着走 |

四条状态共用**同一个正方框**，只改颜色与附加元素，因此四态之间的切换读起来是
「同一个对焦点在变」，而不是「换了个图标」。

## 2. 四态规范

| 状态 | CSS 变量 | 图形 | 热点 | 触发条件 |
| --- | --- | --- | --- | --- |
| 正常 | `--cursor-default` | 白色方框（线宽 1px + 内外各 1px 深色衬底） | `16 16` | `html` 默认，靠继承覆盖全站 |
| 悬停可点 | `--cursor-pointer` | 同形同位，面层转绿 | `16 16` | `a` / `button` / `[role=button]` / `[role=tab]` / `summary` / `label[for]` |
| 按下 | `--cursor-active` | 绿框 + 中心小框（内框 : 外框 = 1 : 2） | `16 16` | 上述可交互元素的 `:active` |
| 拖拽 | `--cursor-drag` | 绿框 + 环绕 8 枚小点（正方形排布，各带深色衬底） | `16 16` | `.progress-rail__track`、`.viewer__zoom.is-zoomed` / `.is-dragging` |

约定：

- **热点统一取几何中心**。四态都是对称图形，热点落在正中意味着「点击点 = 对焦框中心」，
  与取景器的心智一致。这是相对旧版（箭头热点在箭尖）的一处刻意改变。
- **热点值随挂载尺寸走**：挂载 32px 时是 `16 16`；改挂载尺寸必须同步改热点，
  否则点击位置会整体偏移（构建脚本会按 `HOTSPOT × CSS_SIZE / GRID` 自动算）。
- **不做「可拖拽但未按下」的独立第五态**。拖拽语义由一个图形承担：拖曳过程本身
  已经把「正在动」表达清楚了，再叠一层光标状态是冗余信息。
- **禁用态与文本态交还系统光标**：`:disabled` / `[aria-disabled='true']` → `not-allowed`；
  `input` / `textarea` / `[contenteditable]` → `text`。自定义图案会让人误以为还能点、
  或者以为不能打字。

## 3. 几何规范

### 3.1 母版栅格

母版 `viewBox` 为 **128×128**，几何中心 `(64,64)` 即热点。CSS 挂载尺寸 **32×32**，
缩放比恰好 **0.25**，因此母版里所有坐标都取 **4 的倍数** —— 4 单位 = 1px，
每条边都落在整数像素上。

| 元素 | 母版坐标（128 栅格） | 32px 下实际像素 |
| --- | --- | --- |
| 面层方框外沿 | 48 → 80（边长 32） | 12 → 20（8px） |
| 面层线宽 | 4 | 1px |
| 面层内孔 | 52 → 76 | 13 → 19 |
| 底衬外沿 | 44 → 84（边长 40） | 11 → 21（10px） |
| 底衬线宽 | 12 | 3px（露出 1px + 面层 1px + 露出 1px） |
| 按下态内框外沿 | 56 → 72（边长 16） | 14 → 18（4px） |
| 按下态内框线宽 | 4 | 1px |
| 拖拽态点阵半边长 | 36 | 9px（正方形 4 角 + 4 边中点） |
| 拖拽态绿芯半径 | 4 | 1px（直径 2px） |
| 拖拽态点底衬半径 | 8 | 2px（直径 4px，向绿芯外多露 1px 深色环） |

> **整体尺寸是初版的 50%**。判断口径取「可视包络」= 底衬外沿：现 11 → 21px 共 10px，
> 初版 6 → 26px 共 20px，恰好一半。之所以能精确减半又保持零模糊：包络半宽 5px 是整数，
> 且 5 = 面层半宽 4 + 底衬 1，两个分量都落在整数像素上。
> 面层方框本身是 8px（初版 18px 的 44%）而非 9px —— 见 §8 的取舍说明。

### 3.2 为什么是双层实心，而不是 stroke

本设计语言有一条硬约束：**控件一律不画描边**。但光标有个绕不开的物理约束 ——
它会同时落在**纯白照片**与**近黑界面**两种极端上。纯白方框压在白色照片上会完全消失。

解法：在面层下面垫一圈**更粗的深色实心矩形**，向面层内外各露出 4 单位（32px 下 = 1px）
当作衬底。轮廓留住了，而图形本身一根 `stroke` 都没有 —— 满足规范，也解决了可见性。

实现上用 `fill-rule="evenodd"` 把「外矩形 + 内矩形」两个子路径挖成一个方环：

```
底衬：M44 44H84V84H44Z M56 56H72V72H56Z
面层：M48 48H80V80H48Z M52 52H76V76H52Z
```

### 3.3 按下态：内框 : 外框 = 1 : 2

外框边长 32 → 内框边长 16。内框线宽取 4（与外框相同），让内框在层级上明确退为次要信息。

**内框不再单独画深色衬底**：底衬的内孔正好是 `56..72`，与内框外沿完全重合 ——
也就是说内框天生就被一圈 1px 的深色包着，再补一层纯属重复。少画一层，内框边缘反而更干净。

> 约束：外框边长必须是 **8 的倍数**（既要让 1:2 得整数，又要让线宽 1px 落得下）。
> 32 是当前取值。初版外框 18px 时 1:3 的内框是 6px；现在外框缩到 8px，
> 1:3 要求内框 2.67px —— 既落不到整数像素，也放不下 1px 线宽（线宽一虚，微点就糊成一团），
> 因此取「能被 1px 线宽整除且能围出可见孔」的最大内框 4px，比例随之变成 1:2。

### 3.4 拖拽态：为什么是 8 枚点、为什么排成正方形

- 8 枚取**正方形的 4 个角 + 4 条边的中点**。正方形周长因此被 8 等分，
  相邻两点间距天然全等 —— 正方形上唯一间距均匀的分法。
- **不用 12 枚**：12 枚落在正方形边上会出现「角密边疏」，排布就不再均匀。
- **点与方框的距离显著拉开**：点环半边长 36 单位（9px），点内缘距面层方框外沿 16 单位 = 4px。
  初版是 9 单位 = 2.25px，间隙增大到 1.78 倍；若从用户实际感知的底衬外沿算，
  则是 1.25px → 3px，增大到 2.4 倍。方框缩到 8px 后若点还贴着，整枚光标会糊成一坨噪点，
  拉开距离才读得出「围绕主框的一片区域」。
- **点必须带深色衬底**：r=8 深色圆（4px 直径）垫底、r=4 绿圆（2px 直径）叠上，露出一圈 1px 深色环。
  早先的版本让点裸着，理由是「衬底每边占 1px 会直接把 2px 的点吃掉」—— 这个理由站不住：
  衬底是**向外扩**的，绿芯径根本不变。裸点的实际后果是绿点落在浅色照片、绿色调照片
  或中灰背景上直接消失，而主框靠一圈深色衬底在任何背景上都立得住 —— 两者不一致。
- **点用圆、主框用矩形**：圆无法与像素网格对齐（任意半径的圆边都落在像素内部），
  点的边缘天生带抗锯齿。这是圆形的物理属性而非缺陷 —— 主框是矩形，承担「零模糊」的锚点，
  因此构建脚本的像素对齐自检只跑 `af-normal`，`af-drag` 加进去必然误报。

## 4. 配色规范

data URI 里的 SVG 是**独立文档**，拿不到宿主页面的 CSS 变量（浏览器解析光标图片时
不做变量替换），因此三个颜色只能写死。它们全部来自既有 token，**没有引入任何新数值**：

| 用途 | 实色 | 来源 token |
| --- | --- | --- |
| 底衬（深色） | `#18181A` | `color.material.opaque` = `rgba(24,24,26,.92)` 的等效实色 |
| 面层·正常 | `#F5F5F7` | `color.text.base`（本站的「白」） |
| 面层·悬停/按下/拖拽 | `#30D158` | `color.success`（设计系统里唯一的绿） |

改主色或语义色时，这三处实色必须一起改 —— 这是全项目**唯一允许硬编码颜色**的地方。

> 关于复用 `color.success`：token 规范里 success 是「状态语义色，不参与层级表达」。
> 光标悬停借用它作为交互绿，属于有意的语义扩展 —— 因为设计系统里没有第二个绿色，
> 而「对焦框亮起」在语义上确实贴近「成功/合焦」。这是本规范里唯一一处对
> `设计语言-Token规范.md` §1.3 的偏离，已在此显式备案。

## 5. 技术约束

以下为已确认的问题，修改图标前务必先读：

1. **浏览器光标尺寸上限 128×128**。Chrome / Edge / Firefox 都只接受 ≤128px 的
   `cursor: url()`，超限会**整条声明被丢弃**、静默退回系统箭头。
   因此 256×256 只能做**源文件母版**，CSS 里实际挂载必须是 32×32（或 ≤128）。
2. **原生光标无法做动画**。`cursor: url()` 只渲染一张静态位图，没有任何动画能力。
   拖拽反馈因此全靠「一圈点」这个静态图形表达，**不引入 JS 跟随元素**
   （那要隐藏原生光标、接管所有交互元素，代价远大于收益）。
3. **data URI 里只能写实色，且必须纯 ASCII**。`#` 必须转义成 `%23`；
   中文（如 `aria-label`）属于非 ASCII，未做百分号编码时浏览器可能整条丢弃 ——
   所以 `role` / `aria-label` 在产物里被剥掉了（光标也没有可访问性语义）。
4. **属性引号必须用单引号**。外层是 `url("...")`，内层再用双引号会把 CSS 字符串提前闭合。
5. **`cursor` 可继承**，因此 `html` 上挂一处即全局生效；但 `:where()` 的权重是 0，
   全局规则压不过任何组件级 `cursor`，`width`/`height` 那类写法不要照搬。

## 6. 交付物与构建

```
packages/design-tokens/cursors/
├── src/                      矢量母版（声明尺寸 256×256，带 viewBox，可无限缩放）
│   ├── af-normal.svg         正常 · 白色单点 AF
│   ├── af-hover.svg          悬停可点 · 绿色单点 AF
│   ├── af-press.svg          按下 · 微点 AF
│   └── af-drag.svg           拖拽 · 动态区域 AF
├── preview.html              交互式预览页（含真实光标试区、背景矩阵、像素网格）
└── dist/                     构建产物
    ├── svg/                  母版副本
    ├── png/                  每枚 8 档：256 / 128 / 96 / 64 / 48 / 32 / 24 / 16
    ├── ico/                  每枚一个多尺寸 ICO：16/24/32/48/64/128/256（内嵌 PNG）
    ├── cursors.css           由母版生成的 :root 变量块 —— CSS 的唯一事实源
    ├── preview.svg           联系表预览图（矢量）
    └── preview.png           联系表预览图（2× 栅格）
```

**重新生成**（仓库根目录）：

```bash
npm run build:cursors
```

脚本会做三件事，任何一件不通过都会以退出码 1 失败：

1. **像素对齐自检** —— 把母版几何换算成 32px 下的像素序号，逐点核对颜色，
   并断言整行不出现半透明像素（出现即说明某条边落在半像素上）。
2. **data URI 守门** —— 断言载荷不含未转义双引号、不含非 ASCII。
3. **一致性守门** —— 把生成的声明逐条与 `app.css` 里已回填的值比对。
   **改了 SVG 却忘了回填 app.css 时，这里会直接报错。**

### 关于导出尺寸的取舍

坐标都是 4 的倍数，因此**只有尺寸为 32 的整数倍时边线才落在整数像素上**：

- **像素精确**：`256 / 128 / 96 / 64 / 32`
- **会有轻微重采样柔化**：`48 / 24 / 16`（32 的非整数倍）。这三个是常规图标尺寸，
  为兼容外部场景保留；`16px` 档已接近本图形的可读下限，方框会显得很细。

## 7. 使用方式

### 全局挂载（已在 app.css 末尾落地，无需重复）

```css
html {
  /* cursor 可继承，挂一处即全局生效 */
  cursor: var(--cursor-default);
}

:where(a, button, [role='button'], [role='tab'], summary, label[for]) {
  cursor: var(--cursor-pointer);
}

:where(a, button, [role='button'], [role='tab'], summary, label[for]):active {
  cursor: var(--cursor-active);
}

:where(a, button, [role='button'], [role='tab'], summary, label[for]):disabled,
:where([aria-disabled='true']) {
  cursor: not-allowed;
}

:where(input, textarea, [contenteditable]) {
  cursor: text;
}
```

> `:active` 那条自带 `(0,1,0)` 权重，靠**书写顺序**（文件末尾）压过同为 `(0,1,0)` 的
> 组件级规则 —— 这正是「按下收出微点框」能对照片卡、列表卡这类自定义按钮同样生效的原因。
> 新增组件级 `cursor` 规则时，不要把它写在全局保底规则之后。

### 组件级覆盖

只在语义更强时覆盖，目前只有拖拽类交互需要：

```css
.progress-rail__track,
.viewer__zoom.is-zoomed,
.viewer__zoom.is-dragging {
  cursor: var(--cursor-drag);
}
```

### 在别的应用 / 桌面端复用

`dist/ico/*.ico` 可直接用于 Windows 光标方案（控制面板 → 鼠标 → 指针 →
浏览到对应 `.ico`），`dist/png/*.png` 适合贴文档或做其它平台的资源。
注意这些文件是**为 32px 挂载设计的**，用在需要 48px 以上的场景请改用 SVG 母版重新导出。

## 8. 已知取舍

| 取舍 | 说明 |
| --- | --- |
| 面层方框是 8px 而非 9px | 初版 18px 的一半是 9px（奇数），居中后边线必然压在半像素上，与「整行不出现半透明像素」的守门冲突。8px 与 10px 之间只能二选一，取 8px。因此「精确 50%」落在**可视包络**上，而非面层方框上 |
| 拖拽态总占地是初版的 80% | 点被推远、且带上一圈深色衬底后，图形总跨度 22px（初版 27.5px）。这是「整体缩小 50%」与「点距方框显著增大」两个要求的数学冲突，只能二选一；此处优先满足后者，因为方框本身已缩到 50% |
| 白框在浅色背景上依赖衬底 | 衬底只有 1px（32px 下）。若后续觉得不够，把母版里底衬的露出量从 4 调到 8 即可（面层线宽保持不变），代价是图形整体显粗 |
| 16px 档偏细 | 4 单位线宽缩到 16px 只剩 0.5px，属于物理极限。此档仅供外部场景保底，站内不使用 |
| 悬停绿复用 `color.success` | 见 §4 的备案说明 |
| 热点在中心而非箭尖 | 对称图形取中心更符合直觉，但「精确指向某个像素」的场景（如取色）不如箭头直观 |
| 拖拽态点较小 | 绿芯直径 2px（外面还有 1px 深色环，整体 4px）。绿芯再放大会挤占主框的视觉主导地位，故保持现状 |
