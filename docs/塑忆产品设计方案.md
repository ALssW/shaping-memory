# 塑忆（Shaping Memory）— 产品设计方案

> 版本：v1.0 ｜ 日期：2026-09-22 ｜ 类型：PRD + 技术架构
> 参考开源项目：[PhotoPrism](https://github.com/photoprism/photoprism)、[Afilmory](https://github.com/Afilmory/Afilmory)

***

## 1. 产品概述

### 1.1 项目定位

面向**私人/个人摄影师**的自托管集成系统，将「**作品展示**」「**工具服务**」「**资源管理**」三类能力收敛到同一后端之上，前端通过 Web 前台、Web 后台、移动端三个入口复用同一套 API 与领域模型。

- **私有化**：数据自主可控，隐私优先（参考 PhotoPrism）
- **一体化**：展示、管理、工具三合一
- **跨端一致**：移动端与网页前台功能完全对等

### 1.2 产品愿景

让个人摄影师以最低的维护成本获得「作品集 + 专业管理 + 实用工具箱」三位一体的数字影像资产中心，实现影像资产的长期沉淀与专业管理。

### 1.3 目标用户

| 用户类型      | 核心诉求                |
| --------- | ------------------- |
| 个人摄影师     | 展示作品、管理海量照片、整理 EXIF |
| 摄影爱好者     | 便捷上传、分类归档、使用摄影工具    |
| 系统拥有者（私人） | 权限控制、数据安全、自托管部署     |

## 3. 用户界面（三端）

### 3.1 Web 前台

- 展示高质量照片 + 使用摄影工具
- 瀑布流布局、渐进加载（Blurhash）、平滑缩放
- 照片详情 EXIF 面板
- 公开/私有作品区分

### 3.2 Web 后台

- 资源管理（上传/分类/权限）
- EXIF 编辑
- RBAC 角色与权限配置
- 批量操作

### 3.3 移动端（React Native + Expo）

- 与网页前台**功能完全一致**（同一 `sdk` 与领域类型）
- 复用 `packages/design-tokens/` 的设计 token（`web/tokens.ts`），保证与 Web 端视觉一致
- 额外集成后台管理的移动场景（审核/上传/编辑/权限调整）

## 4. 总体架构

采用 **Modular Monolith + 后台任务队列** 架构：业务收敛于单一 API 服务，图片处理与 AI 分析异步剥离到 Worker，兼顾单机部署简洁性与微服务演进空间。

```
┌─────────────────────────────────────────────────────────────────────┐
│                      客户端 Frontend                                │
│  Web 前台 (Vite+React)    Web 后台 (React Admin)   React Native App │
└──────────────────────────────┬──────────────────────────────────────┘
                               │ HTTP(HTTPS) REST+OpenAPI | WebSocket
┌──────────────────────────────▼──────────────────────────────────────┐
│                   API 服务 Node.js (NestJS/Hono)                    │
│  ┌────────┐ ┌────────┐ ┌──────────┐ ┌──────────┐ ┌───────────────┐  │
│  │ Auth   │ │ Photo  │ │ Album    │ │ Tool     │ │ Admin / RBAC  │  │
│  └────────┘ └───┬────┘ └──────────┘ └──────────┘ └───────────────┘  │
└─────────────────┼───────────────────────────────────────────────────┘
                  │ 发布任务 (BullMQ/Redis)
┌─────────────────▼───────────────────────────────────────────────────┐
│             Worker（可横向扩展）                                    │
│  缩略图(Sharp) · EXIF解析 · AI标签分类 · 元数据写入 · 转码           │
└─────────────────┬───────────────────────────────────────────────────┘
┌─────────────────▼───────────────────────────────────────────────────┐
│ 持久层  PostgreSQL(main+index)  Redis(cache+queue+ws)               │
│ 文件层  本地文件系统(原片/缩略图) ⇄ 可选 S3/OSS 适配器              │
└─────────────────────────────────────────────────────────────────────┘
```

### 4.1 Monorepo 结构

```
shaping-memory/
├── apps/
│   ├── api/                 # API 服务（模块化单体）
│   ├── worker/              # 后台任务 Worker
│   ├── web/                 # 网页前台（Vite + React）
│   ├── admin/               # 网页后台（React + Ant Design）
│   └── mobile/              # React Native 移动端（前台+后台）
├── packages/
│   ├── design-tokens/       # 设计 token 唯一事实源 + Web/React Native 双端产物
│   ├── core/                # 领域模型 / 类型 / 枚举（跨端共享）
│   ├── db/                  # Schema + Drizzle ORM + migration
│   ├── sdk/                 # 统一 API 客户端 SDK（前端/移动端复用）
│   ├── ui/                  # 共享 UI 组件库（设计系统）
│   ├── exif/                # EXIF 解析/编辑封装
│   ├── image/               # 图像处理封装（Sharp）
│   ├── storage/             # 存储适配器（Local/S3）
│   └── config/              # 统一配置与校验
```

> 关键点：移动端与 Web 前台消费**同一个** **`@shaping-memory/sdk`** **与** **`core`** **类型**，从编译期保证功能完全一致，而非靠约定。

## 5. 核心模块详细设计

### 5.1 照片展示系统

- **流式浏览**：瀑布流（Masonic 思路）、Blurhash 渐进占位、Canvas/WebGL 平滑缩放与手势
- **筛选检索**：时间线 / 相册 / 分类 / 标签 / GPS 地图（MapLibre）多维度
- **详情视图**：完整 EXIF 面板（相机、镜头、焦距、光圈、ISO、快门、GPS、色彩空间）
- **分享**：公开相册链接、OpenGraph 社交预览
- **响应式**：共享 `ui` 组件库多断点适配

### 5.2 摄影工具集（插件化）

工具通过 `ToolRegistry` 自描述注册，每个工具声明输入 Schema 并提供纯函数 `compute()`：

```
ToolRegistry
  ├── exposure/       # 曝光三角换算
  ├── dof/            # 景深/超焦距
  ├── fov/            # 焦距-视角
  ├── color_temp/     # 白平衡色温
  ├── composition/    # 构图网格预览
  ├── film_sim/       # 胶片模拟
  └── timer/          # 长曝光/ND 计算
```

前端依据 JSON Schema 动态渲染表单，**新增工具无需改动前端与 API 主流程**。

### 5.3 照片管理后台

- **资源管理**：分片/断点续传、批量重命名、移动/归档/软删除
- **分类体系**：目录分类 + 智能标签 + 人脸 并行
- **EXIF 编辑**：标题、版权、GPS、时间戳，写入 sidecar 或改写文件
- **权限控制**：RBAC 角色、媒体级公开/私有、相册级 ACL
- **移动后台**：复用同一 `sdk`，支持移动审核/上传/编辑/权限调整

## 6. 数据交互逻辑与接口标准

### 6.1 核心数据流（上传 → 展示）

```
上传 ─→ API(校验类型/权限) ─→ 原片落盘 ─→ 记录 media(pending)
  → 发布 job → Worker: 缩略图/EXIF/AI标签 → 更新 media(ready) + WS通知
  → 前台分级请求缩略图 → 详情拉取元数据
```

### 6.2 REST API 统一契约

- **OpenAPI 3.1** 生成文档 + 前端 TS 类型（杜绝类型不一致）
- **统一响应信封**：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "requestId": "req_xxx"
}
```

- **鉴权**：JWT Access + Refresh；RBAC 中间件
- **实时**：WebSocket 推送上传进度/任务状态/审核通知

### 6.3 客户端 SDK 复用

`@shaping-memory/sdk` 提供 `photoApi`、`albumApi`、`toolApi` 等，统一处理鉴权、重试、错误格式化，Web 与移动端共用。

***

## 7. 数据库模型（核心表）

- `users / roles / permissions / user_roles`：账号与 RBAC
- `media`：照片主表（状态、公开性、尺寸、拍摄时间）
- `media_files`：多分辨率分级文件（original/thumbnail/preview）
- `exif_metadata`：完整 EXIF
- `categories / albums / album_media`：分类与相册
- `tags / media_tags`：智能标签
- `tools_history`：工具调用记录
- `jobs`：后台任务（类型、状态、进度、重试）

***

## 8. 关键特性实现方案

| 需求         | 实现方案                                   |
| ---------- | -------------------------------------- |
| 响应式设计      | 共享 UI 库 + Tailwind 断点；明暗主题             |
| 流畅照片浏览     | 分级缩略图 + 懒加载/虚拟滚动 + Blurhash + CDN(可选)  |
| EXIF 查看/编辑 | 解析 `exifr`；编辑 `exiftool`，写后重跑 Index    |
| 高效上传       | 分片上传 + md5 秒传 + 断点续传 + 异步队列 + WS 进度    |
| 数据安全       | JWT+RBAC、HTTPS、文件魔数校验、密钥环境变量、审计日志、定期备份 |

***

## 9. 可扩展性设计

1. **存储适配器**（Afilmory 思路）：`StorageProvider` 接口，适配 NAS/COS/OSS
2. **工具插件化**：自描述注册，可独立灰度/降级
3. **AI 解耦**（PhotoPrism 思路）：标签/人脸识别做成可选 Worker，接本地模型或外部服务
4. **任务队列解耦**：BullMQ 支持失败重试与横向扩容
5. **类型共享**：`core` 单一数据源，全端类型一致
6. **模块边界即服务边界**：模块化单体可平滑拆分微服务

## 10. 技术选型汇总

| 层      | 选型                               | 理由                                        |
| ------ | -------------------------------- | ----------------------------------------- |
| API    | NestJS                           | 模块化强/DI 适合大型单体                            |
| ORM    | Drizzle                          | 类型安全、SQL 透明                               |
| 数据库    | PostgreSQL + Redis               | 元数据索引 + 缓存/队列/WS                          |
| 任务队列   | BullMQ                           | 基于 Redis，成熟可靠                             |
| 图像处理   | Sharp                            | 高性能缩略图/转换                                 |
| EXIF   | exiftool                         | 解析 + 写回                                   |
| Web 前台 | Vite + React + Tailwind          | 响应式、生态成熟                                  |
| Web 后台 | React + Ant Design               | 数据表格/权限组件成熟                               |
| 移动端    | React Native + Expo (TypeScript) | 同 `sdk/` 类型；复用 design-tokens 保证与 Web 视觉一致 |
| 设计系统   | design-tokens（DTCG + 手写双端产物）     | 单一事实源喂 Web 与 React Native，校验脚本守门          |
| 存储     | 本地文件系统 + S3/OSS 适配               | 单机简洁 + 多云弹性                               |
| 部署     | Docker Compose                   | 自托管一键部署                                   |
