## 四、问题清单

### BUG-001 解锁成功后查看器不刷新（严重 · 已修复待复测关闭）

| 字段 | 内容 |
| --- | --- |
| 设备编号 | D1 |
| 严重级别 | 严重（功能可用但结果错误：解锁成功，界面仍显示未解锁状态） |
| 影响模块 | 隐私 · 查看器 · 画廊 |
| 前置条件 | 后台「隐私策略」为 `blur` 且已配置查看密码；成功登录/或使用全局解锁密码 |
| 复现步骤 | 1. 在后台将隐私策略设为 `blur` 并配置查看密码；<br>2. 真机打开画廊，点任意受保护照片进入查看器；<br>3. 点「输入密码解锁」，输入正确密码并提交；<br>4. 观察查看器与背后的缩略图网格 |
| 预期结果 | 解锁成功后，查看器立即由模糊图切换为清晰原片，锁面板消失 |
| 实际结果 | 解锁请求成功（服务端返回票据），**背后缩略图网格已同步转清晰**，但**查看器仍显示模糊图与「这张照片已设为隐私」锁面板**，界面自相矛盾 |
| 复现率 | 必现 |
| 日志 / 截图 | 服务端自检 `POST /privacy/unlock → HTTP 201 {"hasToken":true,"expiresIn":28800}`；设备端 logcat 无任何报错。证据：`shot-r02-viewer-locked.png`、`shot-r05-after-unlock.png` |
| 初步定位 | 移动端 [GalleryScreen.tsx](file:///d:/dev/project/application/shaping-memory/apps/mobile/src/screens/GalleryScreen.tsx#L87-L90) 的 `ViewerTarget` 保存的是**打开瞬间的列表快照**（`{ list, index }`）；解锁广播触发 `usePhotos` 重取并替换 `ordered`，但 `target.list` 仍指向旧数组，[Viewer.tsx](file:///d:/dev/project/application/shaping-memory/apps/mobile/src/screens/Viewer.tsx#L431) 的 `const photo = list[index]` 因此拿到旧的 `privacy.locked` 快照。Web 端 [GalleryScreen.tsx](file:///d:/dev/project/application/shaping-memory/apps/web/src/screens/GalleryScreen.tsx#L239-L252) 拥有「`ordered` 变化 → 按当前照片 id 找回新下标并替换 viewer.list」的同步 effect，移动端缺失，属两端一致性缺口 |
| 修复 | 在移动端 GalleryScreen 补齐与 Web 同口径的同步 effect：`ordered` 变化时按当前照片 id 在新列表中定位并替换 `target.list`，照片被筛掉则夹取合法下标、列表被清空则关闭查看器 |
| 修复验证 | debug 包与 release 包均复测：输入正确密码后查看器立即显示清晰原片、锁面板消失（证据 `shot-r05-after-unlock.png`、`shot-rl04-release-unlocked.png`） |

### 观察项（非缺陷，不影响发布判定）

| 编号 | 内容 | 依据与建议 |
| --- | --- | --- |
